## [2026-05-19 03:25] Phase 2: Terminal-tab zoom

The DanCode client unit-test stack uses jsdom@29, which ships `localStorage` as a bare Object missing `setItem`/`clear`/etc — any feature touching persistence needs a polyfill (now in `client/vitest.setup.js`) before tests will run. xterm.js v6 also removed `setOption('fontSize', N)`; the working knob is `term.options.fontSize = N`, and `attachCustomKeyEventHandler` is the only way to stop xterm from also forwarding zoom keys to the PTY. The plan is `<!-- PARALLEL 1,2 -->` and both worktrees default to the same shellhost-E2E ports (3102/5175) and socket — Phase 1 ran simultaneously and blocked our test until I overrode `DANCODE_E2E_SERVER_PORT` / `DANCODE_E2E_CLIENT_PORT` / `DANCODE_SHELLHOST_SOCKET`; the Ralph orchestrator should set distinct values per worktree before invoking Playwright. The previous hard-coded terminal default of 14 px in `Terminal.jsx` disagrees with the plan's 13 px default — Phase 2 routes this through shared constants in `terminalZoom.js`, so any future per-terminal feature should reuse those rather than re-introducing a local default.

## [2026-05-19 03:26] Phase 1: File-tab zoom

Node 22's experimental built-in `localStorage` shadows jsdom's working implementation but is broken without `--localstorage-file`; the fix was an in-memory shim in `client/vitest.setup.js` that future client tests can rely on without per-suite mocks. CodeMirror's keymap only fires when the view's `contentDOM` has focus, which made the "no effect when focus is outside the editor" criterion satisfied for free — Phase 2 (xterm.js) will not get this freebie and should plan for either an outer `keydown` listener with `document.activeElement` gating or xterm's `attachCustomKeyEventHandler`. The Playwright shellhost E2E had a one-time 401 race on the very first run against a brand-new temp HOME (account-setup race in `e2e-helpers.js`) — the retry succeeded and a freshly-cleaned-port re-run also passed, so it appears to be a pre-existing flake unrelated to the feature, but worth knowing about. The pre-existing `npm test -w server` invocation fails at vitest+tinypool startup on this branch regardless of my changes; the server-side unit suite was unrunnable on master HEAD as well.

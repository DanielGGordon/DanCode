## [2026-06-29 16:46] Phase 0: Toolchain & Compose skeleton

The Gradle wrapper's standard prologue derives `APP_HOME` from `$app_path = $0` relative to CWD; if you `cd` partway through, you also have to pin `app_path` to an absolute path or the later `cd -P "${APP_HOME:-./}"` blows up with a confusing "can't cd to android/" error far below the line you actually changed. AGP 8.7.x is the first 8.7 series with stable `compileSdk = 35` support and still works with Gradle 8.9 + JDK 17 + Kotlin 1.9.24, so the bump from 34 → 35 was a small two-file edit (top-level plugin version + bootstrap SDK pin) plus reinstalling the SDK packages. The Ralph worktree convention works fine in practice — `git worktree add` + symlinking the existing `.toolchain/` into the worktree avoided a multi-GB JDK/SDK re-download. The evaluator's "no source on master" note was the cheapest possible fix (a `--no-ff` merge), but it's worth getting in the habit of landing each phase on master after green so reviewers don't have to be told which branch to check out. A 30-line smoke test in `android/scripts/tests/` was enough to lock in the gradlew CWD-independence behavior; full-blown Gradle-test integration wasn't needed for a wrapper-script fix.

## [2026-06-29 17:09] Phase 1: Vendor & golden-test the terminal core

The Termux `terminal-emulator` library is far more JVM-friendly than its on-device wrapper suggests — `TerminalEmulator` + `TerminalBuffer` only touch `android.util.Base64` (and only inside an OSC 52 path we never exercise), so a `testOptions.unitTests.isReturnDefaultValues = true` flag + a null `TerminalSessionClient` is enough to drive it from pure JUnit; `TerminalSession`/`JNI` (which `loadLibrary("termux")`) stay inert because their static initializers never trigger. Gradle does NOT forward `-D` system properties to forked test JVMs by default — the regenerator wrapper sat silently `Assume`-skipped until I added `testOptions.unitTests.all { systemProperty("regen.goldens", System.getProperty(...)) }`; lesson worth remembering for any property-gated test in this codebase. For a tight snapshot format, putting text / fg / bg / effect on four parallel `|…|` rows (one set per screen row) made diffs read like an actual terminal and was easier to review than JSON. The DECSET/DECRST 1049 + DECSET 1000/1006 sequences exercised by these fixtures are the same ones the Raw-mode auto-engage policy in the plan will react to, so the test data doubles as a concrete contract for that switch later. Finally, gating the regenerator behind a system property + adding a "committed bytes equal canonical bytes" drift check is what makes the fixtures actually stable — without the drift check, hand-edits to `Fixtures.bytesFor()` would silently mismatch the .bin on disk and the snapshot would only catch downstream consequences.

## [2026-06-29 17:10] Phase 2: TLS terminator + login + project dashboard

Robolectric is mandatory for any test that touches `org.json.*` because Phase 0's `isReturnDefaultValues=true` silently swaps "Stub!" exceptions for null returns — `JSONObject.toString()` returning null surfaces as a confusing NPE five frames deep at the OkHttp request-body construction site rather than where the stub actually lived. Pin reproducibility is best served by committing the self-signed cert (so the SHA-256 SPKI in `network_security_config.xml` matches across checkouts) while keeping the key gitignored; a `sync-pin.sh` script that rewrites only the literal `<pin>` element keeps regeneration idempotent. `EncryptedSharedPreferences` under Robolectric is workable with `security-crypto:1.1.0-alpha06` if the impl quietly falls back to plain `SharedPreferences` when master-key creation throws — but that fallback would silently store tokens in cleartext on a real device, so a logged warning in production is a near-term must. The sealed `LoginResult` / `ListResult` pattern keeps the screens dumb and lets the controller decide what 401 *means* (here: invoke `onUnauthorized`, which in `MainActivity.AppNav` clears the token and swaps screens) without leaking nav concerns into the API layer. Compose tests under Robolectric at `@Config(sdk=33)` are about 2s of fixed cost per first test in a class; keep test classes focused so that overhead amortizes.

## [2026-06-29 17:45] Phase 3: One live terminal end-to-end

`TerminalEmulator.reset()` doesn't blank the cell buffer — it resets cursor/effects/DEC flags but the previously-drawn glyphs stay. That's why the reconnect-dedup sink writes RIS + `[?1049l` + `[3J` + `[2J` + `[H` *before* calling `session.reset()`; without that an entire ring-buffer replay is rendered on top of the prior frame and the user sees doubled prompts/output. Termux's `TerminalSession` is `public final class`, so the remote-PTY subclass needed a one-token un-final edit to the vendored source (worth submitting upstream or carrying as a separate patch file so future Termux sync is cheaper). Subclassing also requires the subclass to live in `com.termux.terminal` to see the package-private `mEmulator` / `mClient` fields. The `socket.io-client` engine.io layer constructs its own OkHttp client by default — wire the pinned-TLS client to BOTH `IO.Options.callFactory` and `IO.Options.webSocketFactory` or the WebSocket transport silently bypasses the cert pin. `JSONObject.optString(name, "")` returns `""` for present-but-null fields rather than throwing, so a small `optStringOrNull` helper makes `command`/`cwd` parsing forgiving against either omission or explicit JSON null. The connection-state machine has a non-obvious "buffer resize before connect" requirement: `onSizeChanged` typically fires before the socket finishes the handshake, so `sendResize` must enqueue and replay on `onConnected` — without this the server starts streaming at a stale grid size (or with no size at all if the server didn't seed a default). The Compose-Robolectric assertion vocabulary is missing `assertDoesNotExist()` at this artifact version; use a try/catch on `assertIsDisplayed()` (which throws when the node doesn't match) to express "this node should NOT be present" instead of pinning a different test API.

## [2026-06-29 18:08] Phase 4: Claude Code works (key bar, raw mode, TUI scroll)

The `Write` tool intermittently drops embedded literal ESC (0x1b) bytes when they appear inside multi-character string literals like `"\x1b[?1049h"`, even though a single-byte literal like `ESC = "\x1b"` round-trips fine — so for any test that drives ANSI streams through the emulator, declare `private val ESC = "\x1b"` once and interpolate (`"$ESC[?1049h"`) instead of pasting the byte inline; otherwise tests silently parse the wrong sequence and assertions fail confusingly. Termux's `TerminalEmulator` exposes the two flags Phase 4 needs as `isAlternateBufferActive` and `isMouseTrackingActive` but has no observer for DECSET changes, so a 60Hz `LaunchedEffect` poll into Compose state is the simplest production path — a callback hook would require patching vendored Termux source. Compose `pointerInput` running at `PointerEventPass.Initial` is the right seam for two-finger gesture routing in front of an `AndroidView`, but the wrapper must explicitly call `change.consume()` only on the raw-mode path so the underlying `TerminalView` still receives local-scroll touches via its own `GestureRecognizer`. Robolectric Compose tests treat off-screen nodes in a `horizontalScroll` row as "not displayed", so any test that targets a button past the viewport must `performScrollTo()` before `performClick()` / `assertIsDisplayed()` — a frequent silent failure in tap-bar UIs. Test patterns that exercise UI cycling (Auto → Cooked → Raw → Auto) require the override state to live inside `setContent` as `mutableStateOf` rather than a captured local `var`, or recompositions never see the new value and the cycle appears stuck at the first step.

## [2026-06-29 18:31] Phase 5: Navigation & polish

Compose's `HorizontalPager` lives in `androidx.compose.foundation.pager` (BOM 2024.09 includes it without extra deps), and Robolectric's `composeRule.onNodeWithTag(...).performTouchInput { swipeLeft() }` drives page changes headlessly so swipe acceptance can be tested without an emulator. The Termux `TerminalView.setTextSize(int)` takes pixel units (not sp) and instantiates a fresh `TerminalRenderer` on every call, so wrapping the call in a `lastAppliedFontSize` guard inside `AndroidView.update` is essential — without it every recomposition would tear down the renderer and re-emit a duplicate resize. `TerminalRenderer.mTextSize` and `TerminalView.mRenderer` are package-private, so any size-comparison guard has to live in our own Compose state, not by reading the view back. Declaring `android:configChanges="orientation|screenSize|screenLayout|smallestScreenSize|keyboardHidden|keyboard"` + `windowSoftInputMode="adjustResize"` is the only way to keep the live socket through rotation; `screenLayout` and `smallestScreenSize` are the easy-to-forget ones — without them Android 12+ recreates the activity on certain foldables / split-screen toggles even when the others are listed. The cleanest pattern for "token expiry preserves intended destination" is a headless `AppNavController` with a one-shot `pending` slot guarded by `if (pending == null && current !is Screen.Login)`; this prevents a cascade of 401s (dashboard poller + terminal-list controller firing back-to-back) from clobbering the recovered destination with `Screen.Login`. Sealed `Screen` subclasses that carry the sibling-terminal list inside `Screen.Terminal` made it natural to wire `TerminalSwiper` from the navigation snapshot without re-fetching at the swiper layer. The Compose `pointerInput` stack composes by stacking blocks: putting `detectTransformGestures` (pinch) on one `pointerInput` and the existing two-finger drag on a separate `pointerInput` lets the two coexist without an arbitration loop, but if real-device measurements ever show interference, a unified `awaitPointerEvent` arbiter would be the fix. A pure-Kotlin `PinchZoomDetector` with a per-frame multiplicative accumulator + reset-on-direction-flip is easier to test than wiring directly through Compose's transform callback.
